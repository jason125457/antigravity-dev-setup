# Antigravity Agent Tool Workflow & Best Practices

本手冊規範在 Antigravity 雙腦 / Agent 協作模式下，各工具之調用時機、決策樹與使用規範。

---

## 一、核心開發工具調用原則

| 工具 | 優先級 / 時機 | 嚴格規範與邊界 |
| :--- | :--- | :--- |
| **Serena** | **符號導航最高優先** | 尋找函式、類別、方法之定義、引用、調用鏈時一律優先調用。**嚴禁**在 Serena 可精確定位時進行無差別全文搜尋。 |
| **Context7** | **受版本影響之第三方套件** | **僅在**遇到第三方 API、SDK、前端框架且行為可能因版本變更產生幻覺時調用。專案內部業務邏輯與標準語言特徵不得調用。 |
| **Playwright** | **Web / UI 驗證第一線** | 頁面導航、DOM 狀態快照、Console 錯誤擷取、渲染截圖優先使用 Playwright。 |
| **Chrome DevTools** | **深入除錯備援** | **僅在** Playwright 無法解釋異常，或明確需要 Network Request/Response Body、CDP 協議、Performance Trace 時才啟用。 |
| **Semgrep** | **程式碼變更後掃描** | 僅於實作修改後執行，優先掃描 Changed Files。掃描無命中時**嚴禁使用「零漏洞」或「零缺陷」**，必須嚴謹表述為「在當前規則庫下未檢測到 findings」。 |
| **GitHub MCP** | **授權寫入原則** | 唯讀查詢（commit 狀態、PR 列表）可用於審查；**所有寫入操作（Push、建立 PR、Issue）必須獲得使用者明確許可**。 |

## 二、Document Intelligence 決策樹

處理 PDF、DOCX、PPTX、XLSX（尤其是企業內部機密報告、系統稽核與技術架構文件）時的選擇決策如下：

```
[ 文件解析需求 ]
       │
       ▼
 涉及機密/客戶/內部網路/弱掃？
  ├── 是 ──> 強制本機處理（嚴禁 Cloud API）
  └── 否 ──> 維持本機離線處理（節省外部呼叫）
       │
       ▼
 是簡單文字擷取或純 Office 檔案快速預覽？
  ├── 是 ──> 使用 MarkItDown CLI (毫秒級完成轉換)
  └── 否 ──> 包含複雜排版、長表格、多欄、掃描圖
       │
       ▼
 優先使用 Docling (MCP / Local Converter)
  ├── 具備高精準度表格二維重建與 Markdown 導出
  ├── 產出語意化 JSON AST 與圖表預留標籤 (<!-- image -->)
  └── 解析品質滿足需求？
        ├── 是 ──> 任務完成
        └── 否 (極複雜圖章、跨頁嚴重跑版、特殊視覺裁切需求)
              │
              ▼
         啟用 MinerU Local (-b pipeline 本機離線模型)
          └── 執行深度 OCR、版面偵測與圖片物理裁切導出
```

## 三、機密架構與技術報告解析最佳實踐

1. **表格驗證機制**:
   - 稽核與技術架構報告中的「Firewall 每日阻擋排名」、「IDS/IPS 觸發事件配對」常為跨頁或長表格。
   - 解析後取得 Markdown 表格時，針對 Top 1 來源 IP、阻擋事件總量等關鍵數值，需比對原始 PDF/DOCX 頁面進行交叉驗證。
2. **圖表數值處理**:
   - 圓餅圖與長條圖若未以獨立表格呈現，視覺解析器僅能標記圖片佔位符。
   - 遇此情形，應參考內文之輔助文字描述（如「下圖顯示總連線數為...」），或透過多模態工具檢視該頁局部截圖。
